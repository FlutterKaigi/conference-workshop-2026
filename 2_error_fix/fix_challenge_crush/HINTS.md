# Neon Breakout エラー修正チャレンジ

このブロック崩しゲームには **10 箇所** の問題が仕込まれています。
2 つのフェーズに分けて、すべての問題を修正してください。

| フェーズ | 問題数 | 見つけ方 |
|---|---|---|
| フェーズ 1 | 5 箇所 | `flutter analyze` の結果から見つける |
| フェーズ 2 | 5 箇所 | アプリを動かして、異常な挙動から原因を探す |

> フェーズ 1 の問題が残っているとアプリはビルドできません。必ずフェーズ 1 から取り組んでください。

---

## フェーズ 1: 静的解析で見つかる問題（5 箇所）

```sh
flutter analyze
```

`No issues found!` と表示されるまで修正してください。

### ヒント

- 表示される issue の数と問題の数は一致しません。**1 箇所の原因が複数のエラーを引き起こしている** ことがあります。エラーが出ている場所ではなく、原因の場所を探しましょう。
- `error` だけでなく `warning` も問題の 1 つです。ビルドは通っても、ゲームの挙動はおかしくなっています。
- エディタの「定義へ移動」「参照を検索」を活用しましょう。

<details>
<summary>もう少しヒント</summary>

- 名前のつづりは 1 文字ずつ、大文字小文字まで確認しましょう。
- Dart では `int` と `double` は自動で変換されません。
- `if (x.field != null)` でチェックしても、他のオブジェクトの public なフィールドは null 非許容型に昇格（promotion）しません。
- ローカル変数を宣言すると、同じ名前のフィールドは隠されます（シャドーイング）。

</details>

---

## フェーズ 2: 実行時の異常な挙動（5 箇所）

フェーズ 1 を終えたらアプリを起動して、以下の症状を再現し、原因を修正してください。

```sh
flutter run
```

### チート機能

ステージをクリアせずに次のステージへ進めます。再現作業に活用してください。

- デスクトップ: 左サイドバーの **SKIP STAGE** ボタン、または **[N]** キー
- モバイル: 上部バーの **⏭** ボタン

### 症状 1: マルチボールでボールが暴走する

- **再現手順**: 水色の **M** カプセルをパドルで取る
- **症状**: ボールが 3 個ではなく大量に増える。コンソールに例外が出る

<details>
<summary>もう少しヒント</summary>

コンソールの例外の種類に注目しましょう。リストを `for` で回している最中に、そのリスト自身に要素を追加するとどうなるでしょうか。

</details>

### 症状 2: ライフが 0 になってもゲームオーバーにならない

- **再現手順**: ボールを 3 回落とす
- **症状**: ハートが全部消えても次のボールが用意され、もう 1 回落とすまでゲームオーバーにならない

<details>
<summary>もう少しヒント</summary>

ライフが減った後の判定条件を、境界値（ライフ = 0）で確かめてみましょう。

</details>

### 症状 3: リトライすると前回のブロックが消えたまま

- **再現手順**: ブロックをいくつか壊してからゲームオーバーになり、リトライする（**[R]** キーでのやり直しでも再現）
- **症状**: 前回壊したブロックが消えた状態でステージが始まる。全部壊した後のステージに戻ると、発射した瞬間にステージクリアになる

<details>
<summary>もう少しヒント</summary>

ステージの「定義（設計図）」と、プレイ中に壊れていく「ゲームの状態」が同じオブジェクトを共有していないか確認しましょう。信頼できる単一の情報源（SoT）はどちらでしょうか。

</details>

### 症状 4: モバイル画面の LAUNCH ボタンでボールが発射されない

- **再現手順**: ウィンドウ幅を狭くして（840px 未満）モバイルレイアウトにし、下部の **LAUNCH** ボタンを押す
- **症状**: ボールがその場で固まって動かなくなる。画面タップやスペースキーでの発射は正常

<details>
<summary>もう少しヒント</summary>

正常に発射できる操作と、できない操作では、それぞれ何を呼び出しているでしょうか。UI 層がゲームの状態を直接書き換えると、何が抜け落ちるでしょうか（レイヤードアーキテクチャ）。

</details>

### 症状 5: 硬いブロックがすぐ壊れる

- **再現手順**: チートでステージ 2 に進み、硬いブロック（2 回で壊れるはず）にボールを当てる
- **症状**: 硬いブロックが 1 回で壊れる。ステージ 3 の鉄ブロック（3 回で壊れるはず）も 2 回で壊れる

<details>
<summary>もう少しヒント</summary>

ブロックの体力（`health`）を減らしている場所をすべて探しましょう。「当たったかどうかを判定する」関数が、判定以外の仕事もしていないでしょうか（単一責務の原則）。

</details>

---

## 修正の確認

```sh
flutter analyze
flutter test
```

両方とも問題なく通り、上の 5 つの症状が再現しなくなればクリアです。
